Argo Versioning

Argo Versioning provides version management, change tracking, and streamlined configuration for Argo Workflows in EOxHub Workspaces. It is built on the open-source software gitargo developed by EOX.

After using and providing standard Argo UI within EOxHub workspaces, one larger limitation we found was how users could keep track of changes to their workflow definitions. In a collaborative environment, it was also difficult to know if a colleague had changed something, or what exactly they had changed. That is why we developed the open-source software gitargo, which is made available as Argo Versioning to highlight exactly that aspect.

Key Capabilities¶

Argo Versioning tries to provide all aspects needed for working with workflows throughout their lifecycle:

Workflow Versioning & Change History¶

As illustrated in Figure 1 and Figure 2, Argo Versioning maintains a complete audit trail of workflow definitions. Users can inspect past versions, track who modified a workflow, compare differences between versions in the diff view, and revert to previous states when necessary.

Execution Tracking & Status¶

Users can monitor the latest workflow runs directly within the application interface. As shown in Figure 3 and Figure 4, the run history provides real-time status updates, step-by-step execution logs, and output details for ongoing and completed executions.

Integrated Resource Overview¶

To aid in performance optimization and capacity planning, Argo Versioning includes an integrated resource overview (see Figure 5). This feature displays peak resource usage metrics, such as CPU utilization, memory consumption, and storage demands, for individual workflow executions and steps.

Profile Logic for Cloud & Kubernetes Configuration¶

Configuring complex cloud and Kubernetes parameters such as node selectors, pod tolerations, and resource allocations can be error-prone and tedious when editing raw workflow manifests.

In order to support users with configuration of important cloud and Kubernetes configurations, Argo Versioning introduces profile logic mirroring the profile definitions used in JupyterLab. As shown in Figure 6, these profiles let you automatically configure tolerations, node selection, resource configuration, etc. by selecting one of them.

Workspace Operating Modes¶

Argo Versioning can run in two operating modes depending on the workspace environment configuration:

  • Team Workspaces: All users within the workspace can view, collaborate on, and execute all available workflows.

  • Workshop Workspaces: Access is scoped so users can only view, manage, and manipulate their own workflows (addressing another limitation of standard Argo UI).
